## 0.7.0架构补充（当前）

六类新设备及品牌定义的真源为src/scenario-catalog.ts，美术为tools/scenario-art.mjs、brand-art.mjs与digital-displays.mjs。新品只面向创造模式，均为静态设备。

DecorRecord仍为version=1，kind新增digital_ad，普通摆件的可选wallFace缺省为空以兼容旧记录。电子广告屏使用独立私有digital_ad_display实体，不复用纸面广告的等比例缩放；尺寸、品牌固定，一个物品对应一款屏。墙面点击的锚点仍为左下角。四类展示实体统一由owner关联持久记录。

普通壁挂使用追加的专属几何变体；旧496项桌面索引原位保留，追加至534；纸面广告23幅，电子屏9款独立索引。摆放时核验支撑、实际占用格及其他摆设的占用；高模型核验上方第二格。未加载格跳过而非移除。相邻墙面的保守格占用可能拒绝同一空气格内的多件摆设，避免穿插。

支撑分类新增stairs，仅upside_down_bit=true时具有完整顶面；正放楼梯拒绝。isWallSupport保持只接纳完整背墙，不能通过surfaceHeight为1推导楼梯可挂广告。

新品牌广告保持像素画规格；电子屏面允许256×256或256×192独立画布及同尺寸MER，128×128边框纹理不发光。仅明确白名单屏幕像素G≤24，不修改全局光照。现有41项电子设备命令保留，冰箱仅改变创造栏分组。

下面的0.6.0具体数量描述保留为历史决策背景；动态现状以PROGRESS为准。

## 产品定位与范围

《方寸食光 / Food & Table》从中西餐、餐具扩展为Minecraft基岩版综合场景装饰包，支持近距离观赏、摆设、广告墙和原有吃喝体验。**后续新增内容仅面向创造模式，不扩展生存获取、经营、燃料或耗材机制。**旧53个菜单配方、18个工作台配方与6种作物继续兼容，不删除旧ID或存档状态。

食品保留中餐／西餐／日料／甜品／饮品五类，配方制作信息与展示目录分离。按用户清单，焦糖布蕾归西餐、铜锣烧归日料、鲜果拼盘／银耳雪梨／红枣莲子汤归中餐，不按通常菜系理解擅自改类。蛋挞沿用原ID精修，不重复新增。

电子设备和家居为静态摆件：系统画面不联网、不运行真实软件，投影仪无光束，NAS／UPS／交换机／打印机／碎纸机无真实业务功能，服务铃无声音，桌面时钟固定10:10。笔记本打开／闭合是不同物品；iPad Air包含妙控键盘，茶盘是不可拆分一体摆件。

目标环境是国际版26.52、Windows和安卓，无实验功能。清单最低引擎为`[1,26,20]`，不是将26.52拼成`[1,26,52]`。目标与最低引擎含义不同，不随意修改。

## 持久摆设与交互

- `DecorRecord.version=1`；字段包括uid、revision、dimension、support、kind、definition、direction、native、slots，以及可选yaw、art、size、tableNumber。
- `kind`为surface／tray／ad／appliance。world动态属性`mcpe_food:decor:<uid>`保存内容，`mcpe_food:decor_serial`负责实例序号。不要随意改前缀或字段含义。
- 三类私有展示实体为surface_display、tray_food_display、advert_display。实体owner／part用于关联和修复，不能把实体是否存在当作料理或设备是否存在的唯一依据。
- 持久记录保存字符串定义ID；客户端使用数值索引。仍将旧surfaceVisuals顺序视为兼容合同，只追加新项。0.6.0保留0.5.4的474项后追加22项至496；广告另有20项顺序，不占桌面索引。
- 普通完整表面与上下／双层半砖使用真实表面高度，下半砖以实体贴面，不填满原半砖。上方空间与锚点必须空闲；一个支撑位置最多一件桌面摆设。
- 支撑来自固定vanilla-data分类：完整表面、半砖、排除项；透明完整玻璃和书架支持，楼梯、箱子、栅栏、流体、植物及未知第三方形状不自动放行。不使用预发行isSolid。
- 广告逐格检查完整背墙、前方空间及同向画面重叠；左下角锚定，向右上展开；三档尺寸不拉伸。
- 菜单用MenuSessions阻止同玩家重复会话。确认后重新核验revision、距离、支撑、手持与背包，使用纯背包计划同步提交／失败回滚，不跨await持有写锁。
- 每20 tick最多核对24条记录。未加载返回undefined并跳过，不应掉落或强制加载；加载时补缺失外观、清重复／孤立实体。保存恢复已用替身测试，真实区块生命周期仍待验收。
- 创造放置不扣手持、玩家拆除不掉落；旧生存／不明来源支撑消失的守恒回收逻辑保留，不据此新增生存玩法。

## 容器、托盘、冰箱与桌号

- 菜品默认器皿不改，旧`<food>_serving`仍有效；替代器皿使用专属组合ID。同类三款盘、三款碗互通；11款饮品通用玻璃杯与马克杯，仅珍品红酒另可用高脚杯。
- 盛装与取餐保存实际器皿；取回食物后留空器皿，食用不再返容器。满背包与失败保持原状。
- 托盘三槽保存实际料理ID，允许70种盘装内容（含7种展示配菜），不枚举全组合；每份≤48方块体，本体65，最大预算209；取餐不额外生成普通盘。
- 六款冰箱（单／双门三色）是独立appliance记录，对应9个私有部件方块。整列检查、同步写入、失败回滚；上下部任一拆除只回收一次，顶面摆件级联清理。禁止活塞拆散，辅助块不进创造栏。
- 桌号牌只有一个创造物品，缺省08；双下拉选01—99，00无效。号码存tableNumber，收回得到通用牌、重放恢复08；并发按revision拒绝旧提交。

## 关键决策与原因

| 决策 | 原因／禁止重走的路径 |
|---|---|
| 使用私有纹理别名和目录 | 曾与原版玻璃发生材质冲突；resource_pack_name本身不提供命名空间隔离 |
| 自定义方块零破坏碎屑 | 用户明确不接受原有破坏粒子；不能通过覆盖原版粒子修复 |
| 普通色图＋PBR能力／MER | 官方灵动视效适配目标；不加RTX专用门槛、不改全局光照；结构正确不等于实机正确 |
| 放置正面与屏幕属性分开 | 无屏路由器、服务器原先跳过正面逻辑；不能再用screenFront是否存在作为摆放开关 |
| 四向朝向而非任意yaw | 用户否定斜放，要求最近东南西北正面朝玩家。位置决定，中心正上方才用视角后备；放后不追踪 |
| 烘焙向后110°的发行坐标 | 用户截图证明旧原生X旋转显示方向与离线预览不一致；不能仅把110填进旋转字段 |
| 共用1/8单位Y网格、深度间隔、台阶贴面 | 独立条带相交与漏掉台阶面会露壳、形成点阵；只查共面／夹角不足 |
| 源图／预览独立于游戏包 | 控制运行包占用，保存可维护源文件；新城市广告采用小幅像素画，旧12幅高清图不降采样 |
| 无损压缩与桌号复用 | 0.5.4大量缩进JSON与重复几何占空间；解析结果／解码像素不变，不以降画质换体积 |

带正面设备用placementFront及相对玩家位置算最近四向，保存可选yaw。旧无yaw记录按direction恢复；已有电子设备斜向yaw在加载时一次性吸附并递增revision。不要全局翻转所有模型；鼠标是否在右侧按正常面对屏幕判定。

## 美术与优化合同

- 新摆件128px有效UV，完整展示≤256方块体，剔除不可见面。杯子保留约原75%尺寸；旧原料／作物／厨具64px色图与32px图标，不在精修范围。
- 食物与器皿分food／ware材质槽。MER：R金属度、G自发光、B粗糙度；屏幕／LED白名单G≤24，不能让整张设备或食品发光。
- 12幅原食品主图由image_gen生成并独立中文排版，源和提示词保留；8幅城市像素广告由city-posters脚本、中文栅格源和配色生成。普通构建不调用外部图像API。
- 新横幅256×128、竖幅128×256、方形256×256；旧海报1024／2048px不改变解码像素。各档世界尺寸共享同一画面。
- build完成预览后才执行optimizeRelease：压紧JSON、PNG无损重编码，桌号99索引共用一份实体牌体几何，方块／实体目录内分别复用相同MER。删除196份重复几何和196份MER文件，不删除原始主图。
- 为兼容历史字节哈希，小型recipes与loot_tables JSON保持原字节。不要对这些生成文件全局格式化；PNG压缩后以解码像素比较，不再仅比较压缩文件字节。
- 已提交`tests/fixtures/v0.5.4-storage.json`及优化测量fixture；新检出不应依赖`.cache/storage-baseline`。PNG缓存可重建。优化器按完整构建末尾单次调用，不应对已优化包反复独立运行来刷新统计。
